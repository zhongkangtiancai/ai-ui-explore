# Sprint 1 结构化页面快照设计

## 1. 目标

Sprint 1 使用 Playwright 对指定 URL 执行有边界的被动采集，生成可校验、可追溯、
经过脱敏的 JSON 页面快照。采集覆盖主页面、iframe 和可见的嵌套滚动容器，但不执行
点击、输入、提交等业务动作，也不调用 LLM。

本阶段验证浏览器采集、iframe 遍历、滚动发现、结构化建模、脱敏和错误降级闭环。
它不宣称能够完整理解应用，也不把“达到采集预算”描述为“已经探索全部内容”。

## 2. 已确认范围

### 2.1 本阶段实现

- Chromium 浏览器下的单 URL 快照采集。
- 主页面、同源 iframe、跨源 iframe、嵌套 iframe 和动态 Frame 的结构化遍历。
- DOM 摘要、可访问性语义、可交互元素和定位提示采集。
- 主滚动区域与表格、列表、侧栏等可见嵌套滚动容器的有边界自动滚动。
- 文本、属性、URL 和错误信息在进入快照模型前的脱敏。
- 局部失败、截断、预算使用和停止原因记录。
- 版本化 JSON 输出、JSON Schema 和 CLI。
- 使用虚构数据的本地浏览器集成测试站点。

### 2.2 本阶段不实现

- 截图、请求正文、响应正文和完整网络抓包。
- 原始 HTML、Cookie、Token、密码和登录状态持久化。
- 点击、输入、提交、分页、“加载更多”或折叠区域展开。
- 登录、SSO、扫码、MFA 和登录状态复用。
- 多页面导航、状态图、自动探索策略和危险动作白名单。
- PostgreSQL、Redis、任务 Worker、FastAPI 采集接口和前端采集页面。
- LLM、Agent、知识推断、权限差异和周期巡检。

截图和网络正文只有在独立安全设计明确脱敏、访问控制和保留策略后才可进入后续
Sprint。

## 3. 架构

采集能力位于后端包内，但不依赖 FastAPI：

```text
CLI → Collector → Browser / Scrolling / Redaction → Models → Writer
```

- `models`：定义页面、Frame、元素、滚动、错误、预算和快照结构。
- `collector`：编排一次采集，执行预算控制、去重和部分失败策略。
- `browser`：封装 Playwright 导航、Frame 访问和页面读取。
- `scrolling`：识别滚动区域并执行有边界滚动。
- `redaction`：在数据进入快照模型前清理敏感内容。
- `writer`：校验并原子写入 JSON，失败时不留下半成品。
- `cli`：解析非敏感参数、调用采集内核并返回稳定退出码。

未来 Worker 直接调用 `collector`，不得把 CLI 进程调用作为内部集成接口。

## 4. CLI

安装后的入口为：

```powershell
.\.venv\Scripts\ai-ui-snapshot.exe `
  --url http://127.0.0.1:9000 `
  --output .\exploration-output\sample
```

CLI 接受 URL、输出目录、总超时、Frame 数量、滚动容器数量、滚动轮次、元素数量和
文本长度等非敏感配置。密码、Cookie、Token 和其他秘密不得通过命令参数传入，避免
进入命令历史或进程列表。

退出码约定：

- `0`：快照完整完成，且没有局部错误或截断。
- `1`：无法生成有效快照。
- `2`：已生成可用快照，但存在局部失败或截断。
- CLI 框架负责返回独立的参数用法错误。

## 5. 快照契约

顶层结构为：

```json
{
  "schema_version": "1.0",
  "snapshot_id": "8df8aa19-6342-47f9-b34c-ff665c54b71f",
  "status": "completed",
  "started_at": "2026-07-29T10:00:00Z",
  "completed_at": "2026-07-29T10:00:10Z",
  "source": {
    "requested_url": "http://127.0.0.1:9000/",
    "final_url": "http://127.0.0.1:9000/",
    "title": "Fixture"
  },
  "limits": {},
  "statistics": {},
  "page": {},
  "frames": [],
  "errors": [],
  "truncated": false
}
```

Pydantic 模型是运行时契约的唯一事实来源，并生成纳入版本管理的 JSON Schema。
实际 CLI 输出必须通过该 Schema 校验。

`status` 只允许 `completed` 或 `partial`。存在可恢复错误或任一截断时使用
`partial`；无法形成有效顶层快照时不写输出文件并由 CLI 返回失败。

### 5.1 Frame

每个 Frame 至少记录：

- 本次快照内稳定 ID、父 Frame ID、层级和遍历顺序。
- 名称、经过脱敏的 URL 和采集状态。
- 脱敏文本摘要、可交互元素和滚动结果。
- 局部错误、截断标记和停止原因。

Frame 动态卸载、超时或受安全策略限制时，不中止其他 Frame。对应节点保留失败状态
和脱敏错误摘要。

### 5.2 元素

每个元素至少记录：

- 所属 Frame、标签、ARIA role、可访问名称和脱敏文本。
- 可见、可用、选中、展开等可观察状态。
- 边界框。
- 经过白名单筛选的 `id`、`name`、`type`、`placeholder`、`aria-*` 和
  `data-testid` 属性。
- role/name、label、test id、id 等定位提示。

定位提示只是观察结果，不承诺在后续页面状态中始终唯一或可执行。快照不保存密码值、
隐藏字段值、完整 HTML 或任意未筛选属性。

### 5.3 错误

错误包含：

- `scope`
- `error_code`
- 脱敏后的 `message`
- `recoverable`
- `occurred_at`

错误消息不得包含秘密、完整响应正文或未筛选页面内容。

## 6. 采集流程

1. 启动不加载历史 Cookie 或登录状态的独立 Chromium 上下文。
2. 打开指定 URL，等待 `DOMContentLoaded` 和有上限的稳定窗口。
3. 建立主页面和 Frame 层级。
4. 采集初始 DOM 摘要、可访问性语义和可交互元素。
5. 识别主滚动区域及可见嵌套滚动容器。
6. 依次滚动主页面、各 Frame 和嵌套滚动容器。
7. 每轮滚动后等待短暂稳定，采集并去重新发现的元素。
8. 连续两轮没有新增元素且滚动高度不再变化时停止当前容器。
9. 达到任一预算时停止相关范围并标记截断。
10. 尽量恢复各容器的原滚动位置。
11. 脱敏、模型校验、Schema 校验并原子写入 JSON。

每个 Frame 将文档滚动元素固定为发现序号 `0`，其余容器只接受非零边界框、
允许滚动的 `overflow` 以及 `scrollHeight > clientHeight + 1` 的可见元素。容器 ID
由 Frame 遍历序号和发现序号组成，在一次页面状态不变的重复采集中保持稳定。

容器发现、`scrollTop` 设置/恢复和滚动指标读取与元素采集使用两个独立的 Playwright
`content_script` selector carrier；页面数据只通过原生 `Locator.get_attribute` 读取。
滚动采集不得通过 main-world `Frame.evaluate` 或 `Locator.evaluate` 读取 DOM，也不得
读取输入值、点击“加载更多”或其他控件。

元素 carrier 在隔离 realm 内用 `WeakMap<Element, opaque id>` 区分 DOM 节点，同一
节点跨滚动保持身份，不同位置的同名同属性节点仍分别保留；opaque ID 只用于采集期
去重，不写入页面属性，也不进入快照。容器稳定判断使用滚动 carrier 自己的
descendant node ID 集合，与全 Frame 输出去重分离，避免其他容器的延迟事件污染
当前容器的连续稳定轮次。

滚动本身可能触发懒加载请求，因此属于受预算约束的采集行为。Sprint 1 不分析或
持久化这些网络请求。

## 7. 默认预算

- 总采集时间：60 秒。
- 最大 Frame：50。
- 每个 Frame 最大滚动容器：20。
- 每个容器最大滚动轮次：30。
- 最大元素总数：5,000。
- 单段文本最大长度：500 字符。
- 序列化 JSON 最大体积：10 MB。

预算可通过非敏感 CLI 参数收紧或放宽。任何预算耗尽都必须记录使用量、停止原因并将
相应范围标记为截断，不得将结果描述为完整探索。

元素预算是页面采集全局可消费预算，不是每轮查询上限。达到上限时，当前容器以
`max_elements` 立即停止，后续容器和后续 Frame 不再执行元素读取或滚动，并标记为
`partial`、`truncated`。

如果序列化结果超过体积上限，采集器按稳定顺序先缩短文本摘要，再移除遍历顺序末尾的
元素，直到结果符合上限，同时将快照标记为 `partial` 并记录体积预算耗尽。Writer
只接受上限内且通过 Schema 校验的数据。

## 8. 脱敏

脱敏发生在采集值进入快照模型之前。默认处理：

- 密码、Cookie、Authorization、常见 Token 和密钥字段。
- 身份证号、银行卡号、手机号和邮箱等常见文本模式。
- URL 中名称表明敏感的查询参数。
- Playwright 和浏览器错误中可能出现的敏感片段。

结果记录脱敏计数和命中的规则类别，不记录被替换的原值。规则允许通过不含秘密的
配置扩展。

脱敏只能降低风险，不能宣称识别所有业务敏感数据。输出目录继续由 `.gitignore`
默认排除，真实业务系统的快照需要遵守企业数据访问和保留制度。

## 9. 测试设计

### 9.1 单元测试

- Pydantic 模型和 JSON Schema。
- 预算参数边界。
- 文本、属性、URL 和错误脱敏。
- 元素去重和截断状态。
- 原子 JSON 写入。
- CLI 成功、局部成功、失败和参数错误退出码。

### 9.2 浏览器集成测试

测试站点使用虚构数据，通过两个本地端口构造不同 Origin，覆盖：

- 普通页面。
- 同源和跨源 iframe。
- 嵌套 iframe。
- 延迟加载及动态卸载 Frame。
- 页面主滚动区域。
- 表格、列表和侧栏等嵌套滚动容器。
- 有限懒加载和无限列表模拟。
- 包含虚构密码、Token、身份证号等敏感测试文本的页面。

测试使用真实 Chromium，不用浏览器 Mock 代替关键行为。

### 9.3 端到端验收

- CLI 能生成通过 JSON Schema 校验的快照。
- 主页面、iframe 和嵌套滚动容器中的新增元素可被发现。
- 无限列表按预算结束并标记 `truncated`。
- 单个 Frame 失败不会丢失其他成功结果。
- 敏感测试值不会出现在 JSON。
- 不产生截图、网络正文、Cookie 或登录状态文件。
- 静态业务内容在重复采集中保持稳定；时间、随机 ID 和耗时等运行字段允许变化。

## 10. 依赖与本地开发

- 后端增加并锁定 Python Playwright。
- Sprint 1 只安装 Chromium。
- 浏览器文件放在项目本地且被忽略的目录，不做全局安装。
- `bootstrap` 和质量检查脚本同步更新。
- Chromium 缺失时给出明确安装提示，不在普通采集命令中静默联网下载。
- 不引入 Redis、数据库、LLM 或新的前端依赖。

联网安装 Playwright 包和 Chromium 浏览器前，需要按工作区规则获得明确确认。

## 11. 完成标准

Sprint 1 完成时，仓库包含设计文档、实现计划、JSON Schema、CLI、采集内核、本地
测试站点、自动化测试和使用文档。全部现有质量检查与新增测试通过，Git 中不存在真实
探索输出、浏览器二进制或敏感数据。
