# Sprint 9 受控只读交互与流程发现设计

## 1. 目标与范围

Sprint 9 在现有受控探索、人工辅助登录、任务管理、权限 UI 可见性比较和统一探索知识包的基础上，补齐 V1 中“动作与流程知识”的最小缺口。

本 Sprint 仅自动执行经白名单允许且不改变业务数据的 UI 交互，并为每个已执行交互生成可追溯步骤记录；随后依据已验证的页面状态变化，将步骤确定性归并为观察到的有向流程图。

成功标准是：一个已启动的受控探索任务可在预算内自动发现并执行允许交互；结果能说明某类 UI 交互在何种页面状态下导致何种后继状态，并附有受限、脱敏的证据引用。系统能够在风险或不确定时停止相应分支，而不尝试推测或绕过限制。

## 2. 非目标

- 不执行输入、提交、删除、审批、发布、支付、授权、上传、下载或任何会改变业务数据、业务状态或权限的操作。
- 不绕过访问控制、反自动化、登录保护、SSO、扫码或 MFA。
- 不将流程图描述为业务流程完成、业务规则、后端数据范围或授权结论。
- 不保存或提交密码、Cookie、Token、浏览器存储、原始 DOM/HTML、网络正文、截图、输入值或浏览器对象。
- 不实现跨进程恢复、数据库、Worker、LLM 推断、测试案例/自动化代码生成或真实外站验证。

## 3. 架构与模块边界

新增“只读交互发现”层，位于现有受控探索 Runner 与 Playwright 采集适配器之间。

- **候选提取器**：只消费已有的脱敏页面、元素和定位器投影，产生可能的只读交互候选；不读取或持久化原始 DOM、HTML 和浏览器运行时敏感对象。
- **交互策略门禁**：按交互类别、元素语义/属性、风险词、唯一定位器、URL/Origin 和预算决定是否允许。没有明确允许即拒绝。
- **只读交互执行器**：只在当前页面执行已获准候选，执行后立即通过现有采集能力获得后继页面状态。它不接受任意 JavaScript、坐标点击或自由文本输入。
- **步骤记录器**：将执行、跳过、失败或暂停的结果写成受限 `InteractionStep` 投影，包含动作类别、脱敏目标摘要、前后状态指纹、证据引用、结果和固定原因码。
- **流程归并器**：以状态指纹作为节点、以已验证步骤作为边，构建确定性 `WorkflowGraph`。未执行、失败、跳过或暂停的候选不成为流程边。

模块必须保持纯模型/策略、浏览器适配和任务编排分离，以便分别单元测试。既有 Runner 的页面状态指纹、状态去重、URL/Origin 风险门禁、动作门禁和预算模型应被复用或在边界上扩展，不重新实现平行安全策略。

## 4. 允许交互和默认拒绝

首个切片只允许以下五类交互：

- `expand` / `collapse`：明确折叠控件的展开与收起。
- `switch_tab`：同页标签切换。
- `open_menu`：打开导航或操作菜单；菜单中的业务操作不得自动点击。
- `paginate`：上一页、下一页或明确页码切换。
- `view_details`：打开详情页、抽屉或只读弹窗。

每个候选须同时满足：可归类为上述类型、唯一且已验证的定位器、非禁用、无提交/表单语义、无危险风险词，并通过当前页面和目标 URL 的安全检查。

出现下列任一情况时，系统不得尝试该候选，并以固定原因码暂停当前分支或记录跳过：候选类别未知、定位器不唯一、风险词或提交语义、跨 Origin、下载触发、输入要求、导航后状态不稳定、执行或采集失败，以及任一预算耗尽。

## 5. 预算、数据流与流程模型

任务从已完成登录或匿名入口的受控探索开始，先采集初始页面投影。候选提取和门禁按确定性顺序产生可执行项；Runner 在总步骤、每页候选数、流程深度、页面数和状态重复次数预算内依次执行。执行后采集后继状态并记录步骤，重复状态继续沿用现有去重逻辑，不无限扩展。

每个 `InteractionStep` 至少关联：安全步骤 ID、来源任务 ID、白名单动作类别、脱敏目标摘要、前后状态指纹、受限证据引用、执行结果和固定停止/跳过原因。它不包含敏感输入、可重放脚本或浏览器句柄。

`WorkflowGraph` 的节点是已采集状态指纹，边是一次已验证的 `InteractionStep`。节点和边由受限输入确定性排序；相同起止状态与动作语义的重复步骤被归并，并保留有界的证据引用。图只表达“观察到某类 UI 交互导致状态变化”，不表达业务含义。

任务详情和 `exploration-knowledge-package-v2` 增加步骤、流程节点/边、覆盖和暂停统计及相应知识缺口。包继续保持 `inferences=[]`；未覆盖时保留 `actions_not_explored`，并新增或细化只读交互和流程观察的局限性说明。

## 6. 失败处理与安全语义

当候选不能安全分类、定位不唯一、执行超时、采集失败、URL/Origin 风险、下载触发或页面状态无法稳定时，系统停止该分支，不重试危险动作。任务可返回 `partial`，但流程图只能包含已验证边；未执行、失败或暂停不会伪装成已发生流程。

所有 API、Vue 详情和统一知识包仅暴露脱敏白名单字段。错误响应与审计信息使用固定安全原因码，不回显候选原文、异常文本、认证状态或浏览器运行时对象。

## 7. 验证策略

每个新行为必须先写失败测试，再实现最小代码。验证范围包括：

- 白名单允许与默认拒绝；风险词、提交语义、输入、下载和跨 Origin 的拦截。
- 候选排序、唯一定位器、预算、页面状态去重和停止语义。
- 前后状态与证据引用闭包、步骤/流程图的确定性、重复步骤归并。
- `partial`、失败、跳过和暂停不产生已验证流程边，且只导出不确定性与知识缺口。
- API、任务详情和统一知识包的 Schema、固定错误面及敏感 fixture 扫描。
- 本地虚构站点与真实 Chromium 的端到端验收，覆盖允许交互、风险暂停和受限流程输出。

本地验收不能外推为真实外站、SSO、扫码、MFA 或业务权限验证可用。

## 8. 取舍

本设计选择声明式白名单、状态验证和有界流程图，而不是通用点击尝试或人工录制回放。它优先保证默认拒绝、证据追溯和可测试性，代价是首个切片只覆盖有限交互类型，且不会发现需要输入、确认或业务提交的流程。更广的动作覆盖必须在后续独立设计中逐类评估风险、证据和人工确认策略。
