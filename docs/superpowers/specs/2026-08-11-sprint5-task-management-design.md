# Sprint 5：任务管理 API 与最小操作界面设计

## 目标

将当前仅能由代码调用的受控探索能力，包装为本地可管理的任务流程：创建任务、查看进度与审计、人工登录后确认继续、取消任务和查看脱敏结果摘要。

## 范围与明确限制

- 使用单进程内存任务注册表与后台线程；服务重启后任务、运行结果和登录态均不可恢复。
- 浏览器登录态只存在当前 Browser Context 内存中；不得写入 Cookie、Token、密码、storage state、截图或网络正文。
- 只支持现有只读受控探索；URL/Origin、动作门禁、预算、任务绑定和终态清理继续由 Sprint 4 机制执行。
- 仅使用本地 HTTP fixture 验收；不访问真实外部站点、不绕过访问控制、不自动填写登录表单。
- 不实现 PostgreSQL、Redis、Worker、任务恢复、加密状态存储、SSO/MFA/扫码、截图/网络正文、LLM 推断、权限差异或测试代码生成。

## 架构

### 任务注册表与服务

`ExplorationTaskRegistry` 是进程内、加锁的任务句柄仓库。每个条目包含不可序列化的运行时对象（任务、后台线程、受限运行时）及可序列化的脱敏视图（状态、阶段、审计事件、结果摘要）。运行时对象绝不进入 API 响应。

`ExplorationTaskService` 负责校验创建请求，构造既有 `NavigationPolicy`、`ExplorationTask`、预算、Runner 以及可选 `HumanLoginSession`，并启动后台线程。线程以现有 Runner 运行；完成、部分完成、取消或异常均通过既有任务终态与浏览器关闭闭环收尾。

### API

```
POST /api/v1/exploration-tasks
GET  /api/v1/exploration-tasks/{task_id}
GET  /api/v1/exploration-tasks/{task_id}/events
POST /api/v1/exploration-tasks/{task_id}/confirm-login
POST /api/v1/exploration-tasks/{task_id}/cancel
GET  /api/v1/exploration-tasks/{task_id}/result
```

创建请求显式提供模块入口、目标 Origin、可选认证 Origin、探索预算，以及选择人工登录时的认证 URL、登录后 URL 前缀和 CSS 检查点。服务不从页面推断这些配置。

`confirm-login` 只表示用户已在本机可见浏览器完成操作；服务仍执行现有 Origin、URL 前缀和 CSS 检查点验证。请求不携带账号、密码、Cookie 或验证码。

未知任务、服务重启后的旧任务、非法状态迁移和运行时失败都返回固定安全错误码；不返回 URL 查询参数、选择器、浏览器异常或敏感状态。

### 最小前端

新增任务页面仅包含：创建表单、任务状态/阶段、最小审计事件、等待人工登录提示与确认按钮、取消按钮、结果摘要。前端通过轮询详情接口刷新状态；不展示或保存任何登录凭据。

登录字段只在用户勾选“需要人工登录”后显示。等待状态提示用户到可见浏览器完成登录，再点击“我已完成登录，继续验证”。结果只展示页面/元素/链接计数、任务状态与脱敏来源摘要。

## 数据流

1. 用户提交创建表单；后端校验显式配置和预算，注册内存任务并返回任务 ID。
2. 后台线程开始只读探索；非登录任务直接运行。登录任务打开非无头浏览器并停在 `paused_for_human`。
3. 前端轮询显示暂停原因。用户完成浏览器内登录后调用确认接口。
4. 后端验证当前 Context 的目标 Origin、登录后前缀及 CSS 检查点；成功才继续 Runner，失败保持暂停。
5. Runner 结束或异常时任务终态、审计和浏览器释放同步完成；前端读取脱敏结果摘要。

## 失败处理与安全

- 取消是幂等的；终态任务不能再次确认、取消或获取运行时 collector。
- 后台线程异常进入既有失败终态；清理回调逐个隔离，避免一个清理错误阻断浏览器关闭。
- API 只序列化白名单字段；审计与摘要不能含 Cookie、Token、密码、验证码、storage state 或原始浏览器对象。
- 进程异常终止不保证 finally 执行；该限制须在界面和文档中明确，不应宣称任务恢复或跨进程清理。

## 验收

- 后端 API 测试覆盖创建、查询、取消、未知任务、非法确认、登录确认成功/失败和脱敏响应。
- 本地 fixture 端到端覆盖创建登录任务、暂停、模拟人工登录、确认、探索完成、读取摘要和终态关闭。
- 前端组件测试覆盖创建表单、运行中、等待登录、失败、完成和 API 错误；生产构建通过。
- 完整回归继续覆盖 Sprint 1–4；不因新增 API/UI 放宽 URL、动作或登录态安全规则。

## 方案选择记录

选择“单进程内存注册表 + 后台线程 + 前端轮询”，而非独立 Worker 或数据库队列。理由是以最低部署复杂度先验证可管理任务闭环；可恢复任务、跨进程状态和持久化审计留待后续 Sprint 单独设计。
