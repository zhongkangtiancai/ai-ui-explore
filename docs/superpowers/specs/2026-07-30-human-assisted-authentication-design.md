# AI UI Explorer 人机协同登录设计

## 文档状态

- 日期：2026-07-30
- 状态：已批准
- 批准日期：2026-07-30
- 适用范围：Sprint 2 数据模型预留、未来 Sprint 4 运行时实现
- 不代表：当前代码已经具备人工登录接管能力

## 1. 背景与问题

Sprint 1 已能对公开页面执行受限、只读的结构化探索，但人工验收暴露了两类访问边界：

- 页面可能直接返回访问限制或反自动化提示，技术采集成功不等于获得了目标正文。
- 页面可能只向匿名访问者展示公开外壳，登录后内容无法在当前一次性自动探索中获取。

本设计解决第二类问题：在用户拥有合法访问权限的前提下，允许探索任务暂停，由用户在同一个临时浏览器上下文中手工完成登录，再由系统验证登录结果并继续探索。

本设计不尝试规避验证码、反自动化机制、访问控制、付费墙或网站安全策略。被判断为反自动化阻断的页面必须停止或等待人工处理，不能伪装为登录成功。

## 2. 目标

- 支持系统自动识别“可能需要登录”并暂停，也支持用户主动请求人工接管。
- 用户在独立可见浏览器中手工登录，系统不读取或记录登录凭据。
- 只有用户明确确认“登录完成，继续探索”且验证规则通过后，任务才能恢复。
- 登录后先采集安全检查点，再继续结构化页面探索。
- 整个任务只使用一个临时 Playwright BrowserContext；任务终止后销毁，不持久化登录状态。
- 对访问状态、采集状态和内容完整性分别建模，避免把“请求成功”误判为“内容完整”。
- 全过程保留最小事件审计，并保持事实、证据、推测相互分离。

## 3. 非目标

- 不保存或复用 Cookie、Token、Storage State、密码、验证码或登录表单值。
- 不接管用户日常浏览器，也不复用其已有登录会话。
- 不提供远程浏览器串流、录屏、键盘记录或登录过程截图。
- 不绕过验证码、反自动化、权限控制、付费墙或网站访问限制。
- 不在 Sprint 2 实现可运行的人机协同登录流程。
- 不在本设计中实现多用户会话池、共享账号管理或长期凭据托管。

## 4. 已确认的核心决策

1. 第一版采用“一次任务、一次人工登录、一次临时上下文”。
2. 使用同一个 Playwright BrowserContext 在系统与人工之间交接，不附着用户浏览器。
3. 交互界面优先采用命令行状态控制与独立可见浏览器。
4. 登录触发同时支持自动检测和用户主动接管。
5. 登录完成后必须由用户显式确认，不自动猜测用户是否已经登录。
6. 登录验证使用任务级 URL、必需选择器、缺失选择器条件，并辅以通用安全检查。
7. 可访问域名限定为目标域名及预配置认证域名白名单。
8. 人工处理默认等待 15 分钟；超时后保持暂停，允许用户延长或取消。
9. 只记录最小事件审计，不记录登录过程中的页面正文、表单值、按键、截图或网络正文。
10. 用户提供非敏感身份别名与角色，系统不得根据页面内容推断真实身份。
11. 登录成功后先产生安全检查点，再恢复完整探索。
12. 任务结束后销毁上下文，不输出或复用登录状态。

## 5. Sprint 边界

### 5.1 Sprint 2

Sprint 2 只实现知识模型与运行结果中的必要数据结构及约束：

- `collection_status`
- `content_status`
- `access_status`
- `exploration_status`
- 身份别名与授权范围
- 人工介入记录
- 登录后安全检查点
- 证据与置信度引用

Sprint 2 不启动可见浏览器、不暂停等待人工登录，也不实现认证验证器。

### 5.2 未来 Sprint 4

Sprint 4 才实现运行时能力：

- 状态机与任务控制器
- 自动检测与主动接管
- 可见浏览器交接
- 白名单域名控制
- 人工等待、延长和取消
- 登录结果验证
- 登录后检查点采集
- 最小事件审计
- 上下文销毁及销毁验证

## 6. 总体架构

### 6.1 ExplorationTaskController

探索任务的唯一状态协调者，负责：

- 驱动探索、暂停、验证、恢复和终止。
- 强制执行状态转换条件。
- 将采集状态、访问状态和内容状态分别写入结果。
- 确保所有终止路径都进入上下文清理流程。

### 6.2 BrowserSession

管理一个任务专属的临时 Playwright BrowserContext：

- 自动探索和人工登录共用同一上下文。
- 人工接管期间停止结构化采集。
- 不导出 Storage State，不持久化 Cookie。
- 完成、失败、取消和异常时都必须销毁上下文。

### 6.3 AccessGate

依据可审计信号判断是否需要暂停：

- 登录页或访问限制页面特征。
- 预期内容缺失。
- 任务配置的必需或缺失选择器。
- URL 跳转到允许的认证域名。
- 明确的权限拒绝、限流或反自动化信号。

AccessGate 输出结论、证据和置信度。单独出现“登录”链接不能判定页面必须登录，例如公开页面导航栏中的登录入口。

### 6.4 HumanHandoffCoordinator

负责人工接管生命周期：

- 显示暂停原因和非敏感证据摘要。
- 提供“开始/继续人工处理”“登录完成，继续探索”“延长等待”“取消任务”等命令。
- 管理默认 15 分钟等待窗口。
- 超时后保持暂停，不自动继续探索。

### 6.5 AuthenticationVerifier

在用户明确确认后执行只读验证：

- 当前 URL 是否匹配任务允许的成功 URL。
- 必需选择器是否存在。
- 表示未登录或失败的选择器是否消失。
- 是否仍处于权限拒绝、限流或反自动化页面。
- 当前主机名是否仍在白名单中。

验证失败时返回证据，不把任务标为已认证；用户可以继续人工处理、重新验证或取消。

### 6.6 AuthenticatedCheckpointCollector

验证通过后、恢复完整探索前，采集最小安全检查点：

- 时间戳。
- 当前规范化 URL 与页面标题。
- 通过的验证规则标识。
- 非敏感的页面结构摘要。
- 身份别名和授权范围引用。
- 证据引用与置信度。

检查点不得包含密码、验证码、Cookie、Token、Storage State、登录表单值、网络正文或登录过程截图。

### 6.7 MinimalAuditRecorder

只记录状态事件：

- 任务创建。
- 触发暂停及原因分类。
- 人工接管开始。
- 用户确认、延长或取消。
- 验证开始与结果。
- 检查点创建。
- 探索恢复。
- 上下文销毁结果。

审计记录不得包含页面正文、表单值、按键、剪贴板、Cookie、Token、请求头或响应正文。

## 7. 状态与数据模型

### 7.1 采集状态

`collection_status`：

- `completed`
- `partial`
- `failed`

它只描述采集程序是否完成，不说明内容是否符合预期。

### 7.2 内容状态

`content_status`：

- `expected`
- `unexpected`
- `insufficient_evidence`

它描述采集内容与任务预期是否一致。无法证明时必须使用 `insufficient_evidence`，不能猜测。

### 7.3 访问状态

`access_status`：

- `public`
- `authentication_required`
- `authentication_in_progress`
- `authenticated`
- `permission_denied`
- `anti_automation_blocked`
- `rate_limited`
- `unknown`

反自动化阻断、权限拒绝和登录需求必须明确区分。

### 7.4 探索状态

`exploration_status`：

- `created`
- `collecting`
- `paused_for_human`
- `verifying_authentication`
- `completed`
- `partial`
- `failed`
- `cancelled`

关键转换：

- `collecting -> paused_for_human`：AccessGate 触发或用户主动接管。
- `paused_for_human -> verifying_authentication`：仅在用户明确确认后。
- `verifying_authentication -> collecting`：验证通过且检查点成功创建后。
- `verifying_authentication -> paused_for_human`：验证未通过。
- 任意非终态可因用户取消进入 `cancelled`。
- 所有终态都必须执行上下文销毁。

### 7.5 身份与授权范围

用户在任务开始时提供：

- `identity_alias`：不含账号、邮箱、手机号等敏感信息的别名。
- `role_label`：例如“测试管理员”“普通成员”。
- `authorization_scope`：本次允许探索的业务范围与域名。

系统不得从页面昵称、头像、账号字段或内容推断身份。

### 7.6 人工介入记录

记录以下非敏感字段：

- 介入标识。
- 触发类型：自动或人工。
- 触发原因分类与证据引用。
- 开始、确认、延长、取消和结束时间。
- 验证尝试次数及结果分类。
- 最终状态。

### 7.7 登录后检查点

检查点必须与具体任务、身份别名、授权范围和验证规则绑定。没有成功检查点，不得恢复完整探索。

## 8. 命令行交互流程

未来命令行形式可表达以下任务配置，具体参数名在实施计划中确定：

- 目标 URL。
- 身份别名和角色。
- 目标域名与认证域名白名单。
- 登录成功 URL。
- 必需选择器和应消失选择器。
- 是否使用可见浏览器。

运行流程：

1. 创建一次性浏览器上下文并开始采集。
2. AccessGate 发现登录需求，或用户主动请求接管。
3. 系统停止 DOM、文本和元素采集，状态进入 `paused_for_human`。
4. 命令行显示暂停原因、允许域名和可用操作；可见浏览器保留给用户。
5. 用户手工完成登录。
6. 用户在命令行明确选择“登录完成，继续探索”。
7. 系统进入 `verifying_authentication` 并执行验证规则。
8. 验证失败时显示非敏感原因并返回暂停状态。
9. 验证通过后创建登录后安全检查点。
10. 检查点成功后恢复结构化探索。
11. 任务结束时销毁上下文并记录结果。

等待超过 15 分钟时，任务仍保持暂停，只允许延长等待或取消，不得自动恢复。

## 9. 域名与导航控制

- 使用规范化后的精确主机名匹配，不使用不安全的字符串后缀匹配。
- 默认只允许目标域名和显式配置的认证域名。
- 子域名是否允许必须显式配置，不能由 `endsWith` 一类规则隐式放行。
- 登录期间导航到白名单外域名时立即停止采集并提示用户返回或取消。
- 默认禁止 HTTPS 降级到 HTTP；仅隔离测试环境可显式允许。
- 重定向链中的每个导航目标都需要校验。

## 10. 安全与隐私约束

人工登录期间必须暂停：

- DOM 正文采集。
- 可交互元素采集。
- 输入值读取。
- 页面截图与录屏。
- 网络请求和响应正文采集。
- 键盘、鼠标和剪贴板记录。

系统始终禁止：

- 日志记录密码、验证码、Token、Cookie 或认证请求头。
- 保存或导出浏览器 Storage State。
- 将登录页内容写入结构化快照或知识模型。
- 自动填写凭据或代替用户提交登录。
- 在未经授权的域名继续探索。
- 把登录成功等同于拥有所有数据权限。

敏感信息即使意外出现在异常对象中，也必须在持久化和日志输出前脱敏。

## 11. 事实、证据与推测

所有访问判断必须包含：

- `conclusion`：例如“可能需要登录”或“验证已通过”。
- `evidence`：可复核的非敏感信号引用。
- `confidence`：明确的置信度。

示例边界：

- 页面存在“登录”链接：证据不足，不能判定 `authentication_required`。
- 明确跳转至配置的登录 URL，且目标内容缺失：可判定为高置信度登录需求。
- 登录后内容仍缺失：可能是权限不足、数据条件不足或页面异常，不能直接判定登录失败。
- 返回反自动化错误：标记 `anti_automation_blocked`，不能尝试伪装或绕过。

## 12. 错误处理

| 场景 | 处理 |
| --- | --- |
| 自动检测证据不足 | 保持 `unknown` 或 `insufficient_evidence`，允许用户主动接管 |
| 人工等待超时 | 保持暂停，允许延长或取消 |
| 用户取消 | 标记 `cancelled`，销毁上下文 |
| 登录验证失败 | 返回暂停状态，提供非敏感失败原因 |
| 导航到白名单外域名 | 停止采集，要求返回或取消 |
| 权限拒绝 | 标记 `permission_denied`，不得伪装为登录失败 |
| 反自动化阻断 | 标记 `anti_automation_blocked`，停止自动探索 |
| 检查点创建失败 | 不恢复探索，保持暂停或失败 |
| 上下文销毁失败 | 记录安全错误并使任务失败，不能宣称会话已清除 |
| 进程异常退出 | 执行兜底清理；无法证明清理成功时记录风险 |

## 13. 测试策略

### 13.1 单元测试

- 状态机允许与拒绝的转换。
- 未经用户确认不能进入验证。
- 验证失败不能设置 `authenticated`。
- 没有检查点不能恢复采集。
- AccessGate 的证据和置信度规则。
- 精确域名与子域名白名单规则。
- HTTPS 降级限制。
- 审计字段的敏感信息过滤。

### 13.2 安全测试

- 登录期间不生成 DOM、文本、元素、截图或网络正文记录。
- 日志和异常不包含输入值、Cookie、Token 或认证头。
- 任务结束后上下文被销毁。
- 新任务不能继承上一任务登录状态。
- 白名单外跳转不会继续采集。
- 销毁失败会被识别为安全错误。

### 13.3 本地浏览器集成测试

至少构造两个受控测试站点流程：

- 表单登录。
- 跨域或 SSO 风格登录。

测试必须使用模拟账号和非敏感数据，不以第三方生产网站作为自动化回归依赖。

### 13.4 人工验收

- 登录需求触发后任务正确暂停。
- 用户能在可见浏览器中手工登录。
- 未点击确认时系统不会继续探索。
- 验证失败后可以继续处理、重试或取消。
- 验证通过后产生不含凭据的检查点。
- 登录后页面被结构化探索。
- 任务结束后再次打开相同网站时不保留登录状态。
- 审计记录只包含允许的事件字段。

## 14. 验收标准

未来运行时实现只有同时满足以下条件才可通过：

1. 至少两种受控登录方式完成端到端验证。
2. 人工明确确认是恢复探索的必要条件。
3. 登录验证和检查点都通过后才能恢复采集。
4. 检查点、快照、日志和审计中没有凭据或会话秘密。
5. 所有终止路径均销毁临时上下文。
6. 新任务无法继承旧任务登录状态。
7. 白名单外域名不会被采集。
8. 访问状态、采集状态和内容状态可分别追溯。
9. 每个自动访问判断均包含结论、证据和置信度。
10. 反自动化阻断不会触发绕过行为。

## 15. 已知风险与后续约束

- 通用登录识别存在误判风险，必须允许人工主动接管，并保留 `unknown`。
- SSO 可能涉及多个认证域名；白名单配置过窄会阻断登录，过宽会扩大暴露面。
- 登录成功不代表拥有目标数据权限，仍需独立判断 `permission_denied` 和 `content_status`。
- 浏览器或进程崩溃可能使清理结果无法证明，必须明确记录为风险，不能静默成功。
- 第三方页面结构变化会使选择器验证失效，任务配置需要版本化和可审计。
- 无截图、无正文审计降低了登录过程的可回放性，这是保护凭据所接受的明确取舍。
- 一次性会话会增加重复登录成本，但第一版优先选择安全隔离和可解释性。

- 用户批准本设计文档。

- 明确认证域名白名单的配置与审批责任。
- 明确异常退出时浏览器进程清理的可验证方案。
