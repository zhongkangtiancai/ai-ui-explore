# Sprint 7 探索结果明细与证据浏览设计

## 1. 目标与范围

Sprint 7 为已有的单次受控探索任务提供可读的页面、Frame、元素、链接、定位器候选和证据引用明细。
目标是让用户核验已采集的 UI 结构，并为后续测试案例与 Playwright 自动化代码生成提供可追溯输入。

本 Sprint 只读取已采集的受限证据，不控制浏览器、不回放交互、不新增业务动作。它不实现截图、网络正文、
原始 DOM/HTML 浏览、真实外站验收、登录态持久化、数据库、跨进程恢复、测试案例生成或自动化代码生成。

## 2. 生命周期与安全边界

明细只保存在当前后端进程的任务私有内存中。任务完成、partial、失败或取消后，已完成页面的受限证据
仍可读取；后端重启或任务被未来清理机制移除后不可恢复。

每次 Runner 成功获得 Snapshot 时，将它立即投影为已有的受限 `PageEvidence`、`ElementEvidence` 和
`EvidenceReference`；不保存原始 Snapshot、DOM、HTML、浏览器对象、Cookie、Token、输入值、网络正文或
登录状态。属性白名单、文本/URL/href 脱敏、定位器字段限制均沿用当前 Snapshot/Sprint 6 证据投影规则。

证据引用只保留 Snapshot ID、哈希、schema 版本、JSON Pointer 和有限 excerpt，不复制可恢复的原始 Snapshot。

## 3. 后端模型与采集

复用 Sprint 6 的证据模型，以免单次探索和权限比较在安全字段上分叉：

- `PageEvidence`：页面规范 URL、页面级证据引用、元素列表；
- `ElementEvidence`：Frame 路径、标签、role、可访问名称、有限文本、安全属性、脱敏 href、可见/可用状态、边界坐标、定位器候选和证据引用；
- `EvidenceReference`：受限、可追溯的来源指针。

为单次探索新增任务私有、带锁的 evidence sink。Runner 在每个成功 Snapshot 后调用 sink，任务服务仅从
投影结果计算计数与公开明细，绝不保留 Snapshot。页面和元素数量受既有探索预算及模型上限约束；任何
截断都作为固定原因码和状态展示，而不是完整性结论。

元素列表按 Frame 遍历顺序和元素 `traversal_index` 稳定排序；页面按 Runner 已访问顺序展示。共享模型新增
受限 `LocatorCandidateEvidence`，保存策略、已脱敏参数、推荐级别、唯一性、稳定性、置信度和 Frame 作用域；
现有 `locator_hints` 保留以兼容现有 Sprint 6 数据。定位器候选显示语义、test ID、安全属性、CSS、XPath 与
坐标等观察结果及推荐信息，但不承诺跨页面版本稳定，也不把 CSS/XPath/坐标单独用作跨身份元素匹配依据。

## 4. API 与导出

增加单次探索任务的只读边界：

| Endpoint | 输出 |
| --- | --- |
| `GET /api/v1/exploration-tasks/{task_id}/pages` | 已投影页面列表、Frame/元素/链接计数、采集状态、截断/原因码。 |
| `GET /api/v1/exploration-tasks/{task_id}/pages/{page_id}` | 单页受限 Frame、元素、链接、定位器和证据引用。`page_id` 为任务内安全标识；脱敏 URL 仅用于展示，不能充当唯一键。 |
| `GET /api/v1/exploration-tasks/{task_id}/export` | Schema 校验的 JSON 附件，包含任务元数据和受限页面证据。 |

运行中的任务可读取已完成页面，但接口不暴露浏览器控制能力。未知任务、未知页面和不允许的过滤条件采用固定、
不回显请求输入的安全错误。导出只面向当前进程内的已知任务。

## 5. 前端证据浏览

现有单次任务详情下增加“探索明细”区域：

1. 页面列表显示 URL 摘要、Frame/元素/链接计数、状态和截断提示。
2. 选择页面后显示 Frame 分组与元素表：标签、role、名称、可见/可用状态、链接。
3. 选择元素后显示安全属性、边界坐标、定位器候选、推荐级别和证据引用。
4. 默认显示所有已采集元素；partial、截断和低可靠定位器以明确提示说明限制。
5. 提供 JSON 下载，不写入浏览器本地存储。

前端不提供元素点击、输入、重放、HTML 展示、Cookie/Token 查看或网络请求正文查看。

## 6. 失败语义

- `partial` 任务必须展示已采集页面与固定原因码，不把缺失内容描述为页面不存在或权限拒绝。
- 失败或取消后不再新增证据；已完成证据仍可在当前进程中查看。
- 没有成功页面的任务返回安全空列表，不伪造页面或元素明细。
- 进程重启后任务及证据均不可恢复，客户端得到既有的“任务不存在”安全错误。

## 7. 验证与验收

测试覆盖：

1. evidence sink 只保存受限投影，拒绝 Snapshot/浏览器/敏感值泄露；
2. 任务结束后公开计数与明细一致，partial 保留已采集页面；
3. API 端点的未知资源、JSON Schema、导出与敏感字段扫描；
4. Vue 组件中的页面选择、Frame/元素/定位器展示、partial 提示和下载；
5. 本地 HTTP fixture + 真实 Chromium：探索多个页面后，用户可在 UI 查看管理员、链接与定位器明细；
6. 后端重启后不恢复明细；Ruff、mypy、前端测试/Lint/类型检查/构建和完整回归全部通过。

验收通过只代表“已采集 UI 证据可安全浏览”，不代表页面完整性、业务权限、后端数据权限或自动化代码可直接运行。
