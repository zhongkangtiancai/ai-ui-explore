# Sprint 4：受控探索实施计划

## 实施原则

Sprint 4 分小步落地。每一步必须测试先行，并保持“已实现能力”和“规划能力”分离。

## 第一阶段：风险门禁与状态机

- 新增 `exploration` 包。
- 实现 URL/Origin 规范化与 `NavigationPolicy`。
- 实现 `ActionGate` 的默认拒绝策略。
- 实现任务状态机与最小审计事件模型。
- 覆盖白名单、userinfo、HTTP、危险动作和非法状态转换测试。

## 第二阶段：状态去重

- 基于 Snapshot 1.1 构造页面状态指纹。
- 指纹输入必须脱敏、排序并有预算。
- 覆盖稳定输出、结构变化、URL 变化和预算裁剪测试。

## 第三阶段：有界探索队列

- 实现指定模块入口配置。
- 实现只读导航候选入队与去重。
- 对每个 URL 复用 Sprint 1 Snapshot Collector。
- 覆盖最大页面数、最大深度、重复状态、局部失败测试。

## 第四阶段：人机协同登录运行时

- 实现暂停/确认/验证/恢复状态流。
- 实现认证 URL 与选择器验证骨架。
- 实现登录后安全检查点。
- 构造本地模拟登录站点。
- 覆盖未确认不能恢复、验证失败不能认证、检查点缺失不能恢复、终态销毁上下文测试。

## 第五阶段：文档与验收

- 更新 README、AGENTS、项目上下文、架构和安全文档。
- 提供人工验收步骤。
- 运行完整质量门。

## 当前执行切片

只读导航候选入队、URL 去重、深度预算、页面预算、队列预算、状态去重模型和可注入
Snapshot Collector Port 的有界 Runner 编排，以及复用 Sprint 1 `SnapshotCollector` 的适配器。

确定性提取去重链接导航候选的纯函数。Runner 已默认接入该提取器，并在重复页面状态上
停止继续展开候选。
